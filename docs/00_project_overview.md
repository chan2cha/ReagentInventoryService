# 알러지 검사시약 재고/주문/출고 관리 웹서비스 기획 개요

## 1. 프로젝트 배경

친구 회사는 알러지 의약품 검사시약을 판매하며, 항원 종류가 약 100여 개 존재한다. 각 항원은 계란, 당근 등 항원명만으로 관리되는 것이 아니라 제조번호, 유통기한, 입고일, 현재고가 각각 다르다.

현재는 재고현황판을 수기로 관리하고 있어 다음과 같은 문제가 발생할 수 있다.

- 제조번호별 재고 추적 어려움
- 유통기한 임박 재고 누락 가능성
- 주문 접수와 출고 처리 간 정보 전달 오류
- 재고 수량 직접 수정으로 인한 이력 추적 불가
- 1층 출고 담당자와 2층 주문 담당자의 동시 업무 처리 불편

따라서 엑셀 기반 재고표가 아니라, 내부 사용자용 웹서비스로 관리하는 방향으로 결정한다.

## 2. 프로젝트 목표

이 프로젝트의 목표는 알러지 검사시약의 재고, 주문, 출고 업무를 웹에서 통합 관리하는 것이다.

핵심 목표는 다음과 같다.

1. 항원 + 제조번호 + 유통기한 단위의 정확한 재고 관리
2. 거래처 주문 접수 및 출고 상태 관리
3. 유통기한이 빠른 LOT부터 출고하는 FEFO 방식 적용
4. 출고 시 실제 제조번호와 유통기한 기록
5. 모든 재고 변경 이력 저장
6. 담당자별 권한 분리
7. 데이터 유실 방지를 위한 백업 및 운영 정책 수립

## 3. 주요 사용자

| 사용자 | 주요 역할 |
|---|---|
| 관리자 | 전체 데이터 관리, 사용자/권한 관리, 재고 조정, 이력 조회 |
| 주문관리 담당자 | 거래처 관리, 주문 등록, 주문 상태 확인 |
| 출고 담당자 | 출고대기 주문 확인, 출고 처리, 재고 조회 |
| 조회 사용자 | 재고/주문/출고 이력 조회 |

## 4. 추천 기술 방향

초기 단계에서는 별도 사내 서버나 NAS가 없으므로, 직접 서버를 운영하기보다 클라우드 기반의 관리형 서비스를 사용한다.

추천 구성은 다음과 같다.

| 영역 | 선택 |
|---|---|
| 언어 | TypeScript |
| 웹 프레임워크 | Next.js App Router |
| DB | PostgreSQL |
| ORM | Prisma |
| DB 호스팅 | Supabase PostgreSQL |
| 웹 배포 | Vercel |
| 테스트 | Vitest |

## 5. 핵심 설계 원칙

이 시스템에서 가장 중요한 설계 원칙은 다음과 같다.

> 재고는 항원명 단위가 아니라 `항원 + 제조번호 + 유통기한` 단위로 관리한다.

또한 다음 원칙을 따른다.

- 재고 수량은 임의로 직접 수정하지 않는다.
- 입고, 출고, 조정, 폐기 등 모든 변경은 이력으로 남긴다.
- 출고는 유통기한이 빠른 LOT부터 자동 배정한다.
- 유통기한이 지난 LOT는 출고할 수 없다.
- 재고가 음수가 되는 처리는 허용하지 않는다.
- 업무 데이터는 삭제하지 않고 취소/비활성화 상태로 관리한다.
