# 업무 흐름 정의서

## 1. 전체 업무 흐름

```text
주문 접수 → 출고대기 → LOT 배정 → 출고 처리 → 재고 차감 → 출고 이력 저장
```

회사 구조상 2층에서는 주문을 관리하고, 1층에서는 실제 출고를 담당한다. 웹서비스는 두 부서가 같은 데이터를 기준으로 업무를 처리하도록 연결한다.

## 2. 주문 접수 흐름

1. 주문관리 담당자가 로그인한다.
2. 거래처를 선택한다.
3. 한 개 이상의 주문 시약과 수량을 직접 입력한다.
4. 담당자는 최종 품목과 수량을 확인한다.
5. 주문을 등록한다.
6. 주문 상태는 `접수` 또는 `출고대기`가 된다.

## 3. 출고 처리 흐름

1. 출고 담당자가 로그인한다.
2. 출고대기 주문 목록을 확인한다.
3. 주문 상세를 확인한다.
4. 시스템은 항원별 출고 가능 LOT를 추천한다.
5. 출고 가능 수량은 완제품 창고만 조회하며 추천 기준은 FEFO 방식이다.
6. 출고 담당자가 출고 처리한다.
7. 시스템은 출고 이력을 생성하고 재고를 차감한다.
8. 주문 상태는 `출고완료`로 변경된다.

## 4. FEFO 출고 방식

FEFO는 First Expired, First Out의 약자다. 유통기한이 먼저 도래하는 재고부터 먼저 출고하는 방식이다.

예시:

| 항원 | 제조번호 | 유통기한 | 현재고 |
|---|---|---:|---:|
| 계란 | EGG-001 | 2026-09-30 | 5 |
| 계란 | EGG-002 | 2027-01-31 | 10 |

계란 항원 7개를 출고해야 하는 경우 다음과 같이 배정한다.

| 제조번호 | 배정수량 |
|---|---:|
| EGG-001 | 5 |
| EGG-002 | 2 |

## 5. 입고 흐름

1. 관리자가 신규 LOT를 등록한다.
2. 항원, 제조번호, 유통기한, 입고일, 입고수량과 입고 창고를 입력한다.
3. 선택한 창고의 `WarehouseStock` 수량은 입고수량으로 시작한다.
4. 입고 이력이 자동 생성된다.

## 6. 재고 조정 흐름

재고 조정은 파손, 폐기, 실사 차이 등 예외 상황에서 사용한다.

1. 관리자 또는 출고 담당자가 LOT와 조정 대상 창고를 선택한다.
2. 조정수량과 사유를 입력한다.
3. 시스템은 해당 창고의 현재고를 증감한다.
4. 재고 조정 이력을 생성한다.
5. 조정 후 현재고가 음수가 되면 저장할 수 없다.

## 7. 창고 간 재고 이동 흐름

1. 관리자 또는 출고 담당자가 재고 현황에서 LOT와 출발 창고를 선택한다.
2. 도착 창고, 이동할 양의 정수 수량과 사유를 입력한다.
3. 시스템은 출발 창고의 충분한 재고를 조건부로 차감하고 도착 창고 재고를 증가시킨다.
4. 출발과 도착이 같거나 출발 재고가 부족하면 전체 요청을 취소한다.
5. 부분 수량 이동을 허용하며 LOT 전체 수량은 변하지 않는다.
6. `TRANSFER` 재고 이력 한 건과 `STOCK_TRANSFER` 감사 로그를 같은 Serializable 트랜잭션에 저장한다.
7. 폐기 창고로 옮기는 것은 격리 이동이다. 실물 폐기가 끝났을 때 별도 폐기 처리로 해당 창고 수량을 차감한다.

## 8. 출고 취소 흐름

출고 취소는 신중하게 처리한다.

1. 관리자가 출고 건을 선택한다.
2. 출고 취소 사유를 입력한다.
3. 기존 출고 수량만큼 완제품 창고 재고를 복구한다.
4. 출고취소 이력을 생성한다.
5. 출고 상태는 `취소`로 변경한다.
6. 관련 주문 상태도 필요에 따라 `출고대기` 또는 `취소`로 변경한다.

## 9. 엑셀 자료 내보내기 흐름

1. 관리자, 주문관리 담당자 또는 출고 담당자가 로그인한다. 조회 사용자는 `DATA_EXPORT` 권한이 없어 메뉴, 화면의 바로가기와 다운로드 API를 사용할 수 없다.
2. `/lots`, `/movements` 또는 `/orders`에서 `현재 조건 엑셀`을 누르면 현재 검색·필터·기간에 일치하는 전체 결과를 내려받는다. 선택 조건은 페이지 이동에도 유지되며 화면의 20건 페이지 범위에는 제한되지 않는다.
3. 더 세밀한 조건이나 통합 파일이 필요하면 `/exports`로 이동한다.
4. 재고 현황과 입출고 이력을 각각 내려받거나, 원하는 자료를 선택해 한 통합 파일로 만든다.
5. 재고 현황은 검색어, 창고와 계산된 재고 상태를 선택할 수 있고, 입출고 이력은 검색어, 창고, 이동 구분 및 한국 시간 기준으로 시작일과 종료일을 모두 포함하는 기간을 지정할 수 있다.
6. 서버는 인증과 권한 및 보고서별 허용 조건을 다시 확인한 뒤 DB를 직접 조회한다. 통합 자료와 이력 참조는 동일한 `Repeatable Read` 스냅샷을 사용하고, 조회 실패 시 예시 데이터로 대체하지 않는다.
7. 각 자료가 10,000건을 초과하거나 셀·전체 문자 예산 또는 생성 파일 4,000,000바이트를 초과하면 파일을 반환하지 않고 검색 또는 기간 조건을 좁히도록 안내한다.
8. 파일은 생성자·생성시각·필터·건수의 `내보내기정보` 시트와 선택된 `재고현황`, `입출고이력` 또는 `주문내역` 시트로 구성한다. 주문은 품목당 한 행으로 기록하고 취소 상태도 보존한다.
9. 입출고이력 시트에는 원본 `기록 수량`과 실제 재고 영향인 `재고 증감`을 함께 기록해 출고와 복구의 방향을 명확히 한다.
10. 생성 성공 후 `INVENTORY_EXPORT`, `MOVEMENT_EXPORT`, `ORDER_EXPORT`, `COMBINED_EXPORT` 중 해당 감사 로그를 저장하고 나서 파일을 제공한다. 감사 로그 저장에 실패하면 파일도 제공하지 않는다.

## 10. 상태 전이

### 주문 상태

```text
접수 → 출고대기 → 출고완료
접수 → 취소
출고대기 → 취소
```

### 출고 상태

```text
출고완료 → 취소
```

## 11. 예외 상황

| 상황 | 처리 방식 |
|---|---|
| 재고 부족 | 출고 불가 메시지 표시 |
| 완제품 외 창고에만 재고 존재 | 일반·교환 출고 가능 수량에서 제외 |
| 창고 이동 수량 부족 또는 동일 창고 선택 | 출발·도착 재고와 이력을 모두 변경하지 않고 오류 안내 |
| 폐기 창고 이동 | 전체 수량을 보존하고 격리 이동으로 기록; 실물 폐기는 별도 `DISPOSE` 처리 |
| 유통기한 경과 | 출고 대상에서 제외 |
| 주문 취소 | 주문 상태를 취소로 변경, 삭제하지 않음 |
| 출고 후 오류 발견 | 출고 취소 기능으로 재고 복구 |
| 제조번호 오입력 | 관리자만 수정 가능, 수정 이력 저장 권장 |
| 엑셀 내보내기 권한 없음 | 메뉴와 버튼을 숨기고 직접 API 요청도 403으로 거부 |
| 내보내기 시트가 10,000건 초과 | 검색어, 기간 또는 구분 조건을 좁히도록 안내 |
| 생성 XLSX가 4,000,000바이트 초과 | 파일을 제공하지 않고 조건을 좁히도록 안내 |
| 내보내기 DB 조회 또는 감사 기록 실패 | 예시 자료나 미감사 파일을 제공하지 않고 오류 안내 |
