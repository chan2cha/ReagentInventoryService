# 업무 흐름 정의서

## 1. 전체 업무 흐름

```text
주문 접수 → 출고대기 → LOT 배정 → 출고 처리 → 재고 차감 → 출고 이력 저장
```

회사 구조상 2층에서는 주문을 관리하고, 1층에서는 실제 출고를 담당한다. 웹서비스는 두 부서가 같은 데이터를 기준으로 업무를 처리하도록 연결한다.

## 2. 주문 접수 흐름

1. 주문관리 담당자가 로그인한다.
2. 거래처를 선택한다.
3. 주문 시약과 수량을 직접 입력하거나, 검색·선택 세트 필터를 이용해 활성 상태인 공용 주문 세트 한 개를 `기준 세트`로 선택한다. 목록은 최초 6개부터 필요한 만큼 펼칠 수 있다.
4. 기준 세트를 선택하면 기존 개별 품목과 수량은 유지하고 없는 세트 품목만 추가한다. 겹치는 개별 품목 수량이 기본값과 다르면 `구성 수정됨`으로 표시한다.
5. 담당자는 기준 세트와 별도로 품목을 추가하거나 세트 구성 품목을 삭제·교체하고 수량을 수정할 수 있다. 관련 없는 개별 추가 품목은 기준 세트 수정 상태에 영향을 주지 않는다.
6. `기본값 복원`은 선택 세트의 누락 품목과 기본 수량만 복원하며 개별 추가 품목은 유지한다.
7. 다른 세트로 변경하면 확인 후 이전 세트 전용 품목만 교체하고 개별 품목은 유지한다. 세트 해제 시에도 현재 품목과 수량은 그대로 남는다.
8. 같은 세트를 복원해도 품목과 수량은 누적되지 않는다.
9. 담당자는 최종 품목과 수량을 확인한다.
10. 주문을 등록한다.
11. 주문 상태는 `접수` 또는 `출고대기`가 된다.

세트 적용은 주문 초안을 채우는 동작일 뿐 주문 저장이나 재고 변경을 발생시키지 않는다. 주문 세트는 거래처와 연결하지 않는 공용 데이터이므로 거래처를 바꿔도 동일한 세트를 선택할 수 있다.

### 2.1 주문 세트 관리 흐름

1. 관리자 또는 주문관리 담당자가 `/orders/templates`에 접근한다.
2. 세트명과 선택 설명을 입력하고, 한 개 이상의 활성 시약 및 기본 수량을 순서대로 구성한다.
3. 시스템은 중복 시약, 1 미만 또는 정수가 아닌 수량, 비활성 시약을 거부한다.
4. 세트를 저장하면 세트 본문과 품목, `ORDER_TEMPLATE_CREATE` 감사 로그를 하나의 트랜잭션으로 기록한다.
5. 수정 또는 활성 상태 변경 시 화면에 표시된 `version`과 현재 값을 비교한다. 다른 사용자가 먼저 변경했다면 저장하지 않고 새로고침을 안내한다.
6. 수정, 활성화, 비활성화 작업은 각각 감사 로그에 기록한다.
7. 비활성 세트는 관리 화면에는 남지만 주문 등록 화면에는 표시하지 않는다.

기존 세트에 포함된 시약이 나중에 비활성화되면 해당 세트는 주문 등록에서 적용할 수 없다. 다시 활성화하려면 먼저 모든 구성 시약을 활성 상태로 만들거나 세트에서 비활성 시약을 제거해야 한다.

## 3. 출고 처리 흐름

1. 출고 담당자가 로그인한다.
2. 출고대기 주문 목록을 확인한다.
3. 주문 상세를 확인한다.
4. 시스템은 항원별 출고 가능 LOT를 추천한다.
5. 추천 기준은 FEFO 방식이다.
6. 출고 담당자가 출고 처리한다.
7. 시스템은 출고 이력을 생성하고 재고를 차감한다.
8. 주문 상태는 `출고완료`로 변경된다.

## 4. FEFO 출고 방식

FEFO는 First Expired, First Out의 약자다. 유통기한이 먼저 도래하는 재고부터 먼저 출고하는 방식이다.

예시:

| 항원 | 제조번호 | 유통기한 | 현재고 |
|---|---|---:|---:|
| 계란 | EGG-001 | 2026-09-30 | 5 |
| 계란 | EGG-002 | 2027-01-31 | 10 |

계란 항원 7개를 출고해야 하는 경우 다음과 같이 배정한다.

| 제조번호 | 배정수량 |
|---|---:|
| EGG-001 | 5 |
| EGG-002 | 2 |

## 5. 입고 흐름

1. 관리자가 신규 LOT를 등록한다.
2. 항원, 제조번호, 유통기한, 입고일, 입고수량을 입력한다.
3. 현재고는 입고수량으로 시작한다.
4. 입고 이력이 자동 생성된다.

## 6. 재고 조정 흐름

재고 조정은 파손, 폐기, 실사 차이 등 예외 상황에서 사용한다.

1. 관리자가 LOT를 선택한다.
2. 조정수량과 사유를 입력한다.
3. 시스템은 현재고를 증감한다.
4. 재고 조정 이력을 생성한다.
5. 조정 후 현재고가 음수가 되면 저장할 수 없다.

## 7. 출고 취소 흐름

출고 취소는 신중하게 처리한다.

1. 관리자가 출고 건을 선택한다.
2. 출고 취소 사유를 입력한다.
3. 기존 출고 수량만큼 재고를 복구한다.
4. 출고취소 이력을 생성한다.
5. 출고 상태는 `취소`로 변경한다.
6. 관련 주문 상태도 필요에 따라 `출고대기` 또는 `취소`로 변경한다.

## 8. 엑셀 자료 내보내기 흐름

1. 관리자, 주문관리 담당자 또는 출고 담당자가 로그인한다. 조회 사용자는 `DATA_EXPORT` 권한이 없어 메뉴, 화면의 바로가기와 다운로드 API를 사용할 수 없다.
2. `/lots` 또는 `/movements`에서 `현재 조건 엑셀`을 누르면 현재 검색어와 재고 상태 또는 입출고 구분에 일치하는 전체 결과를 내려받는다. 선택 상태와 구분은 페이지 이동에도 유지되며 화면의 20건 페이지 범위에는 제한되지 않는다.
3. 더 세밀한 조건이나 통합 파일이 필요하면 `/exports`로 이동한다.
4. 재고 현황과 입출고 이력을 각각 내려받거나, 원하는 자료를 선택해 한 통합 파일로 만든다.
5. 재고 현황은 검색어와 계산된 재고 상태를 선택할 수 있고, 입출고 이력은 검색어와 이동 구분 및 한국 시간 기준으로 시작일과 종료일을 모두 포함하는 기간을 지정할 수 있다.
6. 서버는 인증과 권한 및 보고서별 허용 조건을 다시 확인한 뒤 DB를 직접 조회한다. 통합 자료와 이력 참조는 동일한 `Repeatable Read` 스냅샷을 사용하고, 조회 실패 시 예시 데이터로 대체하지 않는다.
7. 각 자료가 10,000건을 초과하거나 셀·전체 문자 예산 또는 생성 파일 4,000,000바이트를 초과하면 파일을 반환하지 않고 검색 또는 기간 조건을 좁히도록 안내한다.
8. 파일은 생성자·생성시각·필터·건수의 `내보내기정보` 시트와 선택된 `재고현황`, `입출고이력` 시트로 구성한다.
9. 입출고이력 시트에는 원본 `기록 수량`과 실제 재고 영향인 `재고 증감`을 함께 기록해 출고와 복구의 방향을 명확히 한다.
10. 생성 성공 후 `INVENTORY_EXPORT`, `MOVEMENT_EXPORT`, `COMBINED_EXPORT` 중 해당 감사 로그를 저장하고 나서 파일을 제공한다. 감사 로그 저장에 실패하면 파일도 제공하지 않는다.

## 9. 상태 전이

### 주문 상태

```text
접수 → 출고대기 → 출고완료
접수 → 취소
출고대기 → 취소
```

### 출고 상태

```text
출고완료 → 취소
```

## 10. 예외 상황

| 상황 | 처리 방식 |
|---|---|
| 재고 부족 | 출고 불가 메시지 표시 |
| 유통기한 경과 | 출고 대상에서 제외 |
| 주문 취소 | 주문 상태를 취소로 변경, 삭제하지 않음 |
| 출고 후 오류 발견 | 출고 취소 기능으로 재고 복구 |
| 제조번호 오입력 | 관리자만 수정 가능, 수정 이력 저장 권장 |
| 주문 세트 동시 수정 | `version` 불일치로 저장을 중단하고 새로고침 안내 |
| 세트에 비활성 시약 포함 | 주문 등록 적용 및 재활성화 차단, 세트 품목 수정 안내 |
| 엑셀 내보내기 권한 없음 | 메뉴와 버튼을 숨기고 직접 API 요청도 403으로 거부 |
| 내보내기 시트가 10,000건 초과 | 검색어, 기간 또는 구분 조건을 좁히도록 안내 |
| 생성 XLSX가 4,000,000바이트 초과 | 파일을 제공하지 않고 조건을 좁히도록 안내 |
| 내보내기 DB 조회 또는 감사 기록 실패 | 예시 자료나 미감사 파일을 제공하지 않고 오류 안내 |
