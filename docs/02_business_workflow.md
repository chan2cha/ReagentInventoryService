# 업무 흐름 정의서

## 1. 전체 업무 흐름

```text
주문 접수 → 출고대기 → LOT 배정 → 출고 처리 → 재고 차감 → 출고 이력 저장
```

회사 구조상 2층에서는 주문을 관리하고, 1층에서는 실제 출고를 담당한다. 웹서비스는 두 부서가 같은 데이터를 기준으로 업무를 처리하도록 연결한다.

## 2. 주문 접수 흐름

1. 주문관리 담당자가 로그인한다.
2. 거래처를 선택한다.
3. 주문 항원을 선택하고 수량을 입력한다.
4. 주문을 등록한다.
5. 주문 상태는 `접수` 또는 `출고대기`가 된다.

## 3. 출고 처리 흐름

1. 출고 담당자가 로그인한다.
2. 출고대기 주문 목록을 확인한다.
3. 주문 상세를 확인한다.
4. 시스템은 항원별 출고 가능 LOT를 추천한다.
5. 추천 기준은 FEFO 방식이다.
6. 출고 담당자가 출고 처리한다.
7. 시스템은 출고 이력을 생성하고 재고를 차감한다.
8. 주문 상태는 `출고완료`로 변경된다.

## 4. FEFO 출고 방식

FEFO는 First Expired, First Out의 약자다. 유통기한이 먼저 도래하는 재고부터 먼저 출고하는 방식이다.

예시:

| 항원 | 제조번호 | 유통기한 | 현재고 |
|---|---|---:|---:|
| 계란 | EGG-001 | 2026-09-30 | 5 |
| 계란 | EGG-002 | 2027-01-31 | 10 |

계란 항원 7개를 출고해야 하는 경우 다음과 같이 배정한다.

| 제조번호 | 배정수량 |
|---|---:|
| EGG-001 | 5 |
| EGG-002 | 2 |

## 5. 입고 흐름

1. 관리자가 신규 LOT를 등록한다.
2. 항원, 제조번호, 유통기한, 입고일, 입고수량을 입력한다.
3. 현재고는 입고수량으로 시작한다.
4. 입고 이력이 자동 생성된다.

## 6. 재고 조정 흐름

재고 조정은 파손, 폐기, 실사 차이 등 예외 상황에서 사용한다.

1. 관리자가 LOT를 선택한다.
2. 조정수량과 사유를 입력한다.
3. 시스템은 현재고를 증감한다.
4. 재고 조정 이력을 생성한다.
5. 조정 후 현재고가 음수가 되면 저장할 수 없다.

## 7. 출고 취소 흐름

출고 취소는 신중하게 처리한다.

1. 관리자가 출고 건을 선택한다.
2. 출고 취소 사유를 입력한다.
3. 기존 출고 수량만큼 재고를 복구한다.
4. 출고취소 이력을 생성한다.
5. 출고 상태는 `취소`로 변경한다.
6. 관련 주문 상태도 필요에 따라 `출고대기` 또는 `취소`로 변경한다.

## 8. 상태 전이

### 주문 상태

```text
접수 → 출고대기 → 출고완료
접수 → 취소
출고대기 → 취소
```

### 출고 상태

```text
출고완료 → 취소
```

## 9. 예외 상황

| 상황 | 처리 방식 |
|---|---|
| 재고 부족 | 출고 불가 메시지 표시 |
| 유통기한 경과 | 출고 대상에서 제외 |
| 주문 취소 | 주문 상태를 취소로 변경, 삭제하지 않음 |
| 출고 후 오류 발견 | 출고 취소 기능으로 재고 복구 |
| 제조번호 오입력 | 관리자만 수정 가능, 수정 이력 저장 권장 |
