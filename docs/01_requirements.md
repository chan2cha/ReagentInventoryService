# 요구사항 정의서

## 1. 기능 요구사항

### 1.1 로그인 및 권한

- 사용자는 로그인 후 시스템을 사용할 수 있다.
- 사용자 역할은 관리자, 주문관리 담당자, 출고 담당자, 조회 사용자로 구분한다.
- 역할별 접근 가능 기능을 제한한다.

| 기능 | 관리자 | 주문관리 | 출고담당 | 조회 |
|---|---:|---:|---:|---:|
| 항원 등록/수정 | 가능 | 불가 | 불가 | 불가 |
| LOT 재고 등록 | 가능 | 불가 | 제한 | 불가 |
| 거래처 등록/수정 | 가능 | 가능 | 불가 | 불가 |
| 주문 등록 | 가능 | 가능 | 불가 | 불가 |
| 주문 세트 관리/사용 | 가능 | 가능 | 불가 | 불가 |
| 출고 처리 | 가능 | 불가 | 가능 | 불가 |
| 재고 조정 | 가능 | 불가 | 제한 | 불가 |
| 이력 조회 | 가능 | 가능 | 가능 | 가능 |
| 엑셀 자료 내보내기 | 가능 | 가능 | 가능 | 불가 |

### 1.2 항원 관리

- 항원 코드를 등록할 수 있다.
- 항원명을 등록할 수 있다.
- 항원 분류를 입력할 수 있다.
- 더 이상 사용하지 않는 항원은 삭제하지 않고 비활성화한다.
- 항원명으로 검색할 수 있다.

### 1.3 LOT 재고 관리

- 항원별 제조번호와 유통기한을 등록할 수 있다.
- 입고일과 입고수량을 등록할 수 있다.
- 현재고를 조회할 수 있다.
- 같은 항원이라도 제조번호 또는 유통기한이 다르면 별도 LOT로 관리한다.
- 재고 현황은 검색어와 정상·재고부족·품절·유통기한 임박·유통기한 만료 상태를 함께 적용하고, 선택 상태를 페이지 이동과 현재 조건 엑셀에 유지한다.

### 1.4 거래처 관리

- 거래처명, 담당자, 연락처, 주소, 메모를 등록할 수 있다.
- 거래처별 주문 및 출고 이력을 조회할 수 있다.
- 거래처는 삭제하지 않고 비활성화한다.

### 1.5 주문 관리

- 주문관리 담당자는 거래처 주문을 등록할 수 있다.
- 하나의 주문에는 여러 항원이 포함될 수 있다.
- 관리자와 주문관리 담당자는 자주 주문하는 여러 시약과 기본 수량을 공용 주문 세트로 등록, 수정, 활성화 또는 비활성화할 수 있다.
- 주문 세트는 특정 거래처에 매핑하지 않으며, 모든 주문에서 공통으로 사용한다.
- 주문 세트는 이름, 설명, 표시 순서, 활성 상태와 한 개 이상의 시약·기본 수량으로 구성한다.
- 주문 세트를 등록, 수정 또는 재활성화할 때는 구성 시약이 모두 활성 상태여야 한다. 이후 구성 시약이 비활성화되면 해당 세트는 주문 등록에 적용할 수 없다.
- 주문 등록 화면에는 활성 주문 세트만 표시하며, 사용자는 한 번의 클릭으로 세트 품목을 주문 초안에 담을 수 있다.
- 한 주문 초안에는 최대 한 개의 주문 세트만 `기준 세트`로 선택할 수 있고, 별도 품목은 개별적으로 추가할 수 있다.
- 선택한 세트의 구성 품목과 기본 수량이 그대로이면 `기준 세트 · 선택됨`, 구성 품목을 제거·교체하거나 수량을 수정하면 `기준 세트 · 구성 수정됨`으로 표시한다. 관련 없는 개별 품목 추가는 기준 세트 수정으로 보지 않는다.
- 신규 선택과 세트 변경은 기존 개별 품목 및 수량을 보존한다. 겹치는 개별 품목의 수량이 세트 기본값과 다르면 `구성 수정됨`으로 표시하며 자동으로 덮어쓰지 않는다.
- `기본값 복원`은 선택한 세트 구성만 다시 추가하고 기본 수량으로 되돌리되, 관련 없는 개별 추가 품목은 유지한다.
- 세트 변경은 확인 후 이전 세트에서 생성된 전용 행만 제거하고 개별 입력에서 유래한 행은 유지한 뒤 새 기준 세트를 적용한다.
- 세트 해제는 현재 품목과 수량을 삭제하지 않고 모두 개별 품목으로 전환한다.
- 세트가 많아져도 세트명, 설명, 시약 코드·이름으로 검색하고 선택된 세트만 필터링할 수 있어야 하며, 목록은 일정 개수씩 점진적으로 표시한다.
- 같은 세트를 복원해도 품목이나 수량이 누적되지 않아야 한다. 최종 주문은 사용자가 주문 저장을 실행할 때만 생성한다.
- 주문 세트 수정과 활성 상태 변경은 화면에 표시된 `version`을 기준으로 비교 후 갱신하여 다른 사용자의 변경을 덮어쓰지 않는다.
- 주문 세트의 등록, 수정, 활성화, 비활성화는 처리자와 함께 감사 로그에 기록한다.
- 주문 상태를 관리한다.

주문 상태는 다음과 같다.

| 상태 | 의미 |
|---|---|
| 접수 | 주문이 등록된 상태 |
| 출고대기 | 출고 담당자가 처리해야 하는 상태 |
| 출고완료 | 출고가 완료된 상태 |
| 취소 | 주문이 취소된 상태 |

### 1.6 출고 관리

- 출고 담당자는 출고대기 주문을 조회할 수 있다.
- 출고 시 시스템은 유통기한이 빠른 LOT부터 자동으로 추천한다.
- 출고 완료 시 재고가 자동 차감된다.
- 출고 이력에는 항원명, 제조번호, 유통기한, 출고수량, 거래처, 처리자가 저장된다.
- 사이드바의 출고 처리 배지는 접수 또는 준비중인 실제 주문 건수를 표시하고, 주문·출고 처리 후 최신 값으로 갱신한다.
- 재고가 부족한 경우 출고를 진행할 수 없다.
- 유통기한이 지난 LOT는 출고 대상에서 제외한다.

### 1.7 재고 이력 관리

- 입고, 출고, 조정, 폐기, 출고취소 등 모든 재고 변경을 기록한다.
- 이력에는 처리자, 처리일시, 변경수량, 사유, 참조 주문/출고 정보가 포함된다.
- 입출고 이력 화면은 검색어와 입고·출고·조정·폐기·출고취소/복구 구분을 함께 적용하고, 선택 구분을 페이지 이동과 현재 조건 엑셀에 유지한다.
- 이력 데이터는 삭제하지 않는다.

### 1.8 대시보드

대시보드에서 다음 정보를 확인할 수 있다.

- 오늘 주문 건수
- 출고대기 주문 건수
- 오늘 출고 건수
- 유통기한 30일 이내 LOT 수
- 재고 부족 LOT 수
- 최근 재고 이동 이력

### 1.9 엑셀 자료 내보내기

- `DATA_EXPORT` 권한은 관리자, 주문관리 담당자, 출고 담당자에게 부여하고 조회 사용자는 제외한다.
- `/lots`에서는 현재 검색어와 재고 상태를, `/movements`에서는 현재 검색어와 구분을 그대로 적용해 현재 페이지가 아닌 검색 결과 전체를 바로 내보낼 수 있어야 한다.
- `/exports`에서는 재고 현황과 입출고 이력을 각각 내려받거나, 선택한 자료를 한 파일의 개별 시트로 통합해 내려받을 수 있어야 한다.
- 재고 현황은 검색어와 정상·재고부족·품절·유통기한 임박·유통기한 만료 상태로 필터링할 수 있고, 시약 코드·이름·분류, 제조번호, 입고일, 유통기한, 초기·현재·안전 수량, 상태, 활성 여부와 메모를 포함한다.
- 입출고 이력은 검색어, 한국 시간 기준 시작일·종료일을 모두 포함하는 기간, 입고·출고·조정·폐기·출고취소/복구 구분으로 필터링할 수 있어야 한다.
- 입출고 이력은 처리일시, 시약과 제조번호, 유통기한, 사유, 참조 유형, 주문번호, 거래처와 처리자를 포함한다.
- 이력 수량은 DB에 기록된 `기록 수량`과 실제 재고 영향인 `재고 증감`을 분리한다. 출고는 음수, 입고와 출고취소/복구는 양수, 조정과 폐기는 기록된 부호를 사용한다.
- 파일에는 생성자, 생성시각, 적용 필터와 건수를 담은 `내보내기정보` 시트와 요청한 `재고현황`, `입출고이력` 시트를 포함한다.
- 한 시트는 최대 10,000건, 최종 XLSX 파일은 최대 4,000,000바이트로 제한하며 초과 시 조건을 좁히도록 안내한다.
- 통합 파일의 재고와 이력 및 이력의 주문 참조는 동일한 읽기 스냅샷을 사용해 시트 간 기준 시점이 어긋나지 않아야 한다.
- Excel 셀 허용 길이와 전체 문자 예산을 생성 전에 검사해 비정상적으로 긴 메모가 서버 메모리를 과도하게 사용하지 않도록 한다.
- 성공한 개별 및 통합 내보내기는 각각 `INVENTORY_EXPORT`, `MOVEMENT_EXPORT`, `COMBINED_EXPORT` 감사 로그로 처리자, 건수와 필터를 기록한다. 감사 로그 저장에 실패하면 파일을 제공하지 않는다.
- 내보내기 조회는 DB 오류 시 예시 데이터로 대체하지 않고 실패 응답을 반환한다.

## 2. 비기능 요구사항

### 2.1 보안

- 로그인하지 않은 사용자는 업무 화면에 접근할 수 없다.
- 화면 노출 여부와 별개로 엑셀 다운로드 API에서도 로그인, 비밀번호 변경 필요 상태와 `DATA_EXPORT` 권한을 다시 검사한다.
- 보고서별로 허용한 검색 파라미터만 받아 잘못된 조건을 무시한 전체 자료 다운로드를 방지한다.
- DB 접속 정보는 브라우저에 노출하지 않는다.
- 환경변수 파일은 저장소에 커밋하지 않는다.
- 관리자 계정은 강한 비밀번호를 사용한다.

### 2.2 데이터 안정성

- 재고 변경은 반드시 트랜잭션으로 처리한다.
- 출고 처리 중 일부 단계만 성공하는 상황이 발생하지 않아야 한다.
- 재고는 음수가 될 수 없다.
- 주문 세트 본문, 구성 품목, 감사 로그는 하나의 트랜잭션으로 저장한다.
- 주문 세트의 수정 및 활성 상태 변경은 버전 비교 후 갱신 방식으로 동시 수정을 감지한다.
- 운영 DB는 직접 수정하지 않는다.

### 2.3 백업

- 운영 DB는 매일 1회 이상 백업한다.
- 주요 배포 전 수동 백업을 수행한다.
- 월말 백업은 별도 보관한다.
- 백업 파일은 최소 2곳 이상에 보관한다.

### 2.4 성능

초기 사용자는 많지 않지만 다음 조회는 빠르게 동작해야 한다.

- 항원명 검색
- 제조번호 검색
- 유통기한 임박 LOT 조회
- 출고대기 주문 조회
- 거래처별 출고 이력 조회
